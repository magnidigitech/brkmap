You already have the **core V1 architecture** in place. I would not add more Google APIs right now. The next step should be making MapOptima operationally reliable and significantly smarter.

### Recommended next development order

**1. Schedule Intelligence & Validation — highest priority**

Before optimization, add a proper constraint/validation layer:

* Candidate working hours
* Fixed-event conflicts
* Travel-time feasibility
* Minimum buffer between events
* Event duration
* Preferred time windows
* Maximum acceptable travel time
* Start/end location
* Impossible schedules
* Late-arrival risk
* Events that cannot fit into the day

The optimizer should return:

```text
SCHEDULE STATUS
✓ Feasible

Events: 14/14
Distance: 126.4 km
Driving: 3h 18m
Buffer: 52 min
Conflicts: 0
Risk: Low
```

If impossible:

```text
SCHEDULE STATUS
⚠ Needs Attention

14 events requested
12 can be scheduled

2 events could not fit:

• Village Meeting – 4:30 PM
• Media Interaction – 5:15 PM

Reason:
Insufficient travel time between fixed appointments.
```

This is more important than adding additional map features.

## 2. Upgrade the Optimizer

Your current two-stage optimizer is a good foundation. I'd evolve it into:

```text
INPUT EVENTS
     ↓
Classify constraints
     ↓
Fixed anchors
     ↓
Build travel matrix
     ↓
Geographical clustering
     ↓
Flexible event insertion
     ↓
Constraint validation
     ↓
Score schedule
     ↓
Generate alternatives
     ↓
Best schedule
```

The scoring should consider:

```text
Travel Time
Distance
Priority
Time-window satisfaction
Waiting
Buffer
Late-arrival risk
Fixed-event protection
Events completed
```

I'd also make the weights configurable rather than hard-coded.
